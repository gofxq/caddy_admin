# 轻量观测与排障设计

## 意图与授权

用户已确认 metrics 方案评审方向，并要求做好计划和优先级后开始实现。面向 Homelab / NAS 的单管理员，目标是从服务配置核对进入排障，保持既有保存草稿、预览、校验、确认发布和在线回滚流程。分阶段实施，各阶段独立交付；本批实现第一阶段，不将未来规划描述为已实现功能。

## 优先级

| 阶段 | 交付 | 进入条件 |
| --- | --- | --- |
| A，本批 | 服务详情、运行核对、最近发布、管理员手动 TCP 检查 | 复用现有认证、发布模型与上游安全策略 |
| B | 可选轻量 metrics、概览少量统计 | Caddy 侧 Host 基数有界；统一生成器管理 metrics；真实校验与确认发布 |
| C | 短期历史趋势和服务统计 | B 通过重载、断采、域名归属和资源限额验收 |
| D | 脱敏访问日志 | 写文件前脱敏；内外模式日志来源和轮转、容量明确 |
| E | 周期探测和告警 | 明确网络视角、未知状态、低流量阈值与通知选择 |

## 第一阶段设计

增加 `/services/$id` 页面和受认证 `GET /api/v1/services/{id}`。详情按稳定服务 ID 查找当前草稿与最新成功发布的服务，分别返回所属域名访问属性；草稿删除但尚未发布的服务仍可查看。两者皆无返回 404，不通过相同域名关联不同 ID。

运行核对使用完整配置指纹，只报告 `matched`（与已发布配置一致）、`drift`（漂移）、`unknown`（无法读取或核对过程中版本变化）和 `pending`（有 applying/uncertain 发布）。它不是应用健康检查。保留草稿与已发布数据，即使 Caddy 不可达。核对超时 3 秒，不返回原始运行 JSON、Admin URL 或异常细节。

最近发布最多返回最近 20 次全局发布中涉及此服务 ID 的 5 条摘要，按 changes 的 before/after ID 过滤。摘要只含发布 ID、版本、状态、时间和回滚来源；界面说明查询窗口，不把一直存在于配置中的服务算作每次都修改。

增加 `POST /api/v1/services/{id}/check-upstream`，请求仅含详情返回的 `expected_hash` 与 `expected_deployment_id`（`runtime.deployment_id`），不接受 URL/IP/端口。仅检查最新成功发布中启用的服务；只有运行核对 matched 且指纹与发布 ID 未过期才能执行。每次复用当前已生效策略校验已发布的数字 IP 地址快照，不重新解析业务上游名称，不访问草稿目标。执行后再次核对指纹、发布 ID 和发布状态，变化时返回 unknown；相同配置 hash 的新发布也使检查失效；不改写配置或启动快照。

TCP 检查从 Manager 发起，超时 3 秒；返回 `reachable`、`unreachable` 或 `unknown`、目标快照、耗时和检查时间。不进行 HTTP/TLS 应用健康判断，不将 TCP 成功作为 HTTPS 证书通过。不持久化结果、不后台定时探测。全实例只允许一个进行中的手动检查，冲突返回 429；不使用发布锁阻塞配置管理。网络错误只返回可操作中文信息，不回显原始异常。

界面保留六项导航，服务名称可进入详情，待发布删除也有入口。详情具有加载、错误、重试、草稿不存在、未发布、运行待核对和移动端布局；详情刷新失败或服务版本变化后旧探测结果失效；配置可保留供核对，但运行状态必须显示无法确认。发布入口复用现有页面，不新增编辑或发布路径。

## 后续阶段约束

Metrics 配置属于完整生成器，内外模式均经预览、校验和确认发布启用；采集器不修改 Admin API。不得静默改写已有快照或历史发布。v2.11.3 中 HTTPS 会允许未知 Host 单独打标签，未在 Caddy 侧解决前不得默认启用 per_host。

先以 30 秒采集、1 分钟聚合、7 天保留作为 B/C 评估基线，不预先实现五级 Rollup。独立数据库 `${DATA_DIR}/observability.db`，文件权限 0600，不进入核心 readiness。指标写入失败、损坏、容量不足时降级，不阻断登录和发布；必须限制响应、series、查询范围、存储和清理工作量。

计数按原始 series 处理重启与配置重载，再做聚合；保留基线、采集边界与缺口。按采集时已发布服务 ID 和 Host 关联，不以当前草稿归属历史。存储 count/sum/bucket 增量，查询时估算 P95，不平均分位数。请求与响应字节口径、403、5xx、完整请求时长、首字节耗时及长连接限制必须对用户明确。

## 验证

第一阶段覆盖新草稿、草稿改名、待删除、ID 与域名复用、成功/失败/待核对发布、Caddy 断联和并发发布；TCP 覆盖固定快照、许可撤销、受保护目标、IPv6、拒绝任意请求目标、超时、并发限制和检查后版本变化；API 覆盖鉴权、首次改密、Origin/CSRF。前端覆盖空状态、重试、状态解释与旧结果失效，mock 同步但不替代真实验证。

运行 `make test`、`make check`、`make build`；新增 TCP adapter 使用临时本机 socket 验证。未改变 Caddy 生成或部署，不因本批启动真实部署或操作生产数据。
