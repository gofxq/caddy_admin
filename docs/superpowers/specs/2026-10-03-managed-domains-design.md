# 多域名管理与精简初始化设计

状态：待用户审阅；尚未修改产品代码。

## 用户意图

取消 Public/Homelab 两类域名及服务分组，使用统一的多域名列表和域名属性。管理员可以在登录后管理域名、访问范围、上游许可及服务器 DNS。Setup 只配置首个通配符域名、管理员凭据和建立安全控制台所需的 DNS、HTTPS 与确认操作；其他设置由首次登录引导承接。用户明确要求 Setup 不配置 LAN/VPN，也不自动绑定初始化设备的来源 IP。

用户补充：支持通过环境变量，或直接在 Compose 的 `environment` 中明文预配置管理员密码与 Cloudflare Token，不要求 secrets 或文件挂载。已经配置的凭据在 Setup 中只确认使用，不重复提供输入框或要求再次填写。此明确要求替代原项目“不将密码与 Token 放入 Compose 环境”的限制，其他认证与凭据保护规则保留。

用户进一步确认：去掉首个域名默认“仅可信网络”的属性。普通 Setup 只登记域名及完成 DNS/证书相关操作；业务访问范围登录后配置，控制台访问保护独立执行。

用户最终明确：Setup 不按来源 IP、内网网段或初始化设备限制访问；初始化完成后也不自动启用控制台来源限制。只要部署入口可达，公网或内网用户均可打开 Setup，初始化后均可访问登录页；管理操作仍须通过管理员认证。LAN/VPN 限制由管理员登录后按需启用，不是首次使用的必经步骤。此要求替代原项目中 Setup 仅内网来源、控制台默认受 `lan_cidrs` 限制的规则。

继续面向专用 Caddy、单实例、单管理员；不新增多上游、路径路由、任意 JSON 编辑器或外部 DNS 提供商。

## 现有实现与改动边界

- `ManagedSettings`、`TargetPolicy`、`CaddyConfig` 使用固定的 `public_domain` / `homelab_domain`；服务使用 `group`。这些字段同时进入校验、配置生成、证书探测和配置导入导出。
- 设置 API 只读；Manager 的 Origin、网络策略和业务策略在启动时读入。新增编辑接口必须同时解决实际运行策略更新，不能仅更新 SQLite。
- 发布已有串行锁、15 分钟校验、幂等键、运行指纹与 `uncertain` 核对；策略变更应复用这条流程。
- Setup 当前要求上游网络非空，自动完成 DNS 写入后才允许初始化；交接已有受限的临时 IP HTTPS 入口。
- 数据库当前只接受 schema v6。此次修改会改变持久化业务模型和配置文件格式，必须明确版本边界。
- 当前 Compose 示例仅提供 `CLOUDFLARE_API_TOKEN_FILE`，没有管理员初始密码来源，也没有 Setup 的凭据预配置确认分支；下文作为本次拟新增能力，不将其描述为已实现功能。

## 方案选择

采用“统一域名列表 + 域名访问属性 + 全局可信网络与上游策略”。这满足多域名的实际需要，又能沿用一套网络策略，减少普通用户重复配置。

不采用仅修改界面名称的方案：固定两个域名仍然不能管理任意数量的域名。不为每个域名增加独立 ACL、独立 Token 或独立 DNS 提供商：当前需求没有要求这些能力，后者还会扩大密钥与证书管理范围。

## 域名与服务模型

域名条目包含：

- `id`：稳定标识，由服务引用。
- `name`：基础域名，例如 `example.com`；界面显示 `*.example.com`。允许粘贴单个前导 `*.`，服务端统一保存基础域名。
- `access`：已配置时为 `trusted` 或 `internet`，界面名称为“仅可信网络”或“允许互联网访问”；未配置为 `null`，显示“待配置”，不默认选择其中任何一种。

这些是访问属性，不再是域名类型或服务分组。每个域名都可选择访问属性，修改属性会影响它下面所有已启用服务，必须在 Diff 中列明并明确确认放开访问。

普通 Setup 创建的首个域名访问属性保持未配置；登录后新增域名同样由管理员明确选择访问范围。未配置时可以登记域名、申请证书和保存服务草稿，但不能发布该域名的启用业务服务；发布前必须明确选择并在预览中确认。登记域名或取得通配符证书本身不创建业务代理路由。显式导入文件已有的访问属性可保留，不视为 Setup 自动赋予默认值。

设置单独保存控制台完整域名和精确 HTTPS Origin，默认 `caddyadmin.<首个基础域名>`。控制台来源限制独立于业务域名属性，`console_lan_only` 默认 `false`；默认不校验来源是否属于 LAN/VPN，也不生成内网拒绝路由。管理员可以登录后显式启用，届时必须配置非空可信网段。仅填写业务使用的可信网段或修改域名属性不会自动启用控制台限制；认证与精确 Origin/CSRF 保护始终执行。

服务使用 `domain_id`，取消 `group`。保留完整 `hostname` 以明确展示路由；它必须是所选基础域名的一层子域，不能占用控制台或交接期间保留的控制台地址。新增服务默认选首个域名，筛选与列表按域名、访问范围展示。

域名做规范化、重复及重叠检查；拒绝会使控制台或一层子域归属不明确的组合。未知 Host 仍返回 404，不因通配符证书存在而代理到默认上游。

域名删除或改名时检查草稿、实际已发布服务和控制台引用。有引用时列出阻塞对象，不自动改写服务 Host、不联动删除；用户先调整相关服务并完成必要发布。控制台所属域名的替换通过单独交接流程完成。

## Setup

流程缩为“管理员 → 首个域名与 DNS → 确认”。域名步骤保留已有 Token 帮助、DNS 变更预览、明确确认、浏览器 DoH 检查和服务器最终复核；保留 HTTP 明文提示和外部 Caddy / 隔离测试说明。

移除独立网络步骤及常规上游许可输入。服务器 DNS 使用当前默认 `1.1.1.1`，有私有 DNS 环境的用户可在必要的高级入口修正；完整 DNS 管理放在登录后。

Setup 不配置 LAN/VPN 范围，不自动生成当前来源的 `/32` 或 `/128` 白名单，不在确认页增加网段确认或网络修正入口。移除现有 Setup 仅允许内网、回环或链路本地 TCP 来源，以及 Host 必须是私网 IP 的限制；保留 HTTP(S) 请求的精确 Origin 匹配、输入校验、初始化状态检查和限速，不把公网来源当作拒绝条件。

普通 Setup 不设置首个域名的业务访问属性，只登记域名并完成 DNS、证书相关操作，登录后由管理员配置业务访问范围。控制台来源限制初始关闭，可信网段初始为空，不套用任何默认内网范围；公网入口可达时可以从公网打开登录页，登录后才能使用管理功能。首次登录后设置页提供可选的“仅允许 LAN/VPN 访问控制台”，管理员明确启用并发布后才生效；启用时 Caddy 与 Manager 执行相同规则，并保留已有可信代理来源校验，不能信任任意转发头。

临时入口不默认增加来源网段或私网 Host 限制，保留认证、精确 Origin 与 CSRF 保护；管理员后来启用控制台来源限制时才同步执行。新入口由浏览器实际访问确认后再关闭临时入口；访问失败不再把用户送回 Setup 配置网段。

初始上游许可网段和许可服务名为空，服务列表为空，尚未配置许可时拒绝创建代理目标并提供下一步指引。空上游策略是合法的初始化状态，含义为不许可任何目标，不是取消安全校验。

初始化导入入口保留为显式高级操作，以免删除现有数据可控能力：新格式可携带域名、策略和草稿，集中核对并确认覆盖默认值；它不增加普通 Setup 的必填项，不导入凭据、不自动发布业务服务。现有实例导入仍只替换草稿，并按本机域名与策略校验。

### Compose 预配置凭据：来源、确认和缺失分支

采用两个直接配置项：`ADMIN_PASSWORD` 为首次管理员密码，`CLOUDFLARE_API_TOKEN` 为 Cloudflare Token。可以在 Compose 的 `environment` 中明文填写，或由环境变量/`.env` 注入；默认均为空。无需创建额外 secret 文件、挂载目录或配置权限。不新增 `ADMIN_PASSWORD_FILE`、Compose secrets 或另一套文件来源选择流程。

直接在 Compose 中填写的示例（下列值均为待替换的占位值）：

```yaml
services:
  caddy:
    environment:
      ADMIN_PASSWORD: "replace-with-your-password"
      CLOUDFLARE_API_TOKEN: "replace-with-your-token"
```

通过环境变量或 `.env` 注入的示例：

```yaml
services:
  caddy:
    environment:
      ADMIN_PASSWORD: ${ADMIN_PASSWORD:-}
      CLOUDFLARE_API_TOKEN: ${CLOUDFLARE_API_TOKEN:-}
```

两个示例任选其一，合并到现有 Compose 服务的 `environment`，其余端口和持久化配置保持原部署要求。Compose YAML 中密码或 Token 含字面 `$` 时使用 `$$`，避免被 Compose 当作插值；文档同步给出这条填写规则。版本控制中的示例只使用占位值，不包含实际凭据。

应用仍自动管理运行时持久化，不要求管理员准备文件：确认使用后将 Token 原子写入 `${DATA_DIR}/secrets/cloudflare_token`，统一用于校验、Caddy 启动与设置页更新；管理员密码按现有规则保存为 Argon2id 哈希。

`ADMIN_PASSWORD` 只用于尚未初始化的实例；再次启动、重建容器或更改该环境变量均不重置已有管理员密码。初始化后的 Token 以持久化运行文件为准，不在重启时用环境变量覆盖设置页更新的值；更新密码和 Token 使用现有登录后的设置入口。已有 `CLOUDFLARE_API_TOKEN_FILE` 运行文件路径配置不作为此次新增的 Setup 凭据预配置入口，也不要求用户使用它。

Setup 状态接口对每项只返回“未配置 / 已配置可用 / 配置有误”及不含敏感信息的原因；不返回内容、长度或可供离线猜测的密码指纹。环境变量未设置或为空视为未配置，显示手动输入；非空但格式不合法视为配置错误，提示修正环境变量，不误报为已配置或静默忽略。

| 预配置情况 | 步骤 1 的密码区域 | 步骤 2 的 Token 区域 |
| --- | --- | --- |
| 两项均已配置且有效 | 显示“管理员密码已通过部署配置”，只确认使用 | 显示“Cloudflare Token 已通过部署配置”，只确认使用 |
| 仅密码已配置 | 同上 | 显示空的 Token 输入框及获取帮助 |
| 仅 Token 已配置 | 显示密码输入、随机生成及显示/隐藏 | 只确认使用，不回显或要求粘贴 Token |
| 两项均未配置 | 沿用手动创建密码 | 沿用手动 Token 输入 |
| 非空环境变量格式无效 | 在对应区域明确阻断，要求修正或清空部署值后重建容器 | 同左；Token 权限另在 DNS 预览时检查 |
| 外部 Caddy 或测试模式 | 密码仍可预配置并确认 | 不使用本地 Token，不提供输入或使用确认，不因它缺失而阻断 |

使用确认默认未勾选。已配置密码时，步骤 1 展示用户名（默认 `admin`，仍可修改）与“我确认使用已配置的管理员密码”；不显示密码输入、随机生成、显示密码或覆盖入口。已配置 Token 时，步骤 2 展示“我确认使用已配置的 Cloudflare Token”；不显示 Token 输入或替换入口，获取权限帮助可按需展开。两项确认不代替 DNS 变更影响确认和最终初始化确认。

浏览器只提交使用预配置凭据的确认，服务端使用环境中的实际值，绝不先把凭据发给浏览器再提交回来。同一次 Setup 使用进程启动时确定的值，不新增动态文件读取、热更新或凭据来源选择器。修改 Compose/环境变量后重建容器，旧页面的凭据使用确认失效，重新读取状态再确认；服务端用不含凭据的 Setup 会话标识拒绝旧进程的确认。Token 改变使 DNS 预览及确认失效；密码改变只使密码使用确认与最终初始化确认失效，不重复写 DNS。沿用结果未知时先核对、不盲目重试的规则。

只确认使用 Token 不代表它已具有目标 Zone 权限；DNS 预览继续使用服务端凭据检查权限、目标记录和冲突。两项凭据齐备也不跳过域名填写、DNS 检查、预检、变更确认或自动执行初始化。

### 进入前：状态与连接检查

- 显示“正在检查初始化状态”；部署模式由服务端确定，不提供内置/外部模式选择器。
- 未初始化时进入步骤 1。数据库或状态接口不可读时显示“无法连接初始化服务”，提供“重试连接”，不能把读取失败当作空实例。
- 同时读取预配置环境变量的可用状态，显示输入或确认；非空无效值不显示为可用，不把任何凭据内容返回前端。
- 已初始化时显示正式控制台地址并提供打开入口，不再次展示创建管理员表单。
- 此前提交过但结果未知时进入结果核对，不能默认重新执行初始化。
- HTTP 入口说明“HTTP 会明文传输手动填写的管理员密码和 Token，建议使用 HTTPS”，并提供“使用 HTTPS 初始化”链接；提示不构成内网来源门禁。HTTPS 临时入口说明可能出现证书信任提示。
- 保留“第一个成功提交者成为唯一管理员”的提示。页面不出现网段输入、当前来源 IP 建议、设备绑定开关或网段确认框。
- 初始化入口不检查来源是否内网，也不要求 Host 为私网 IP；保留精确 Origin 检查和限速。部署的监听、端口映射及宿主防火墙仍决定实际网络可达性，应用不擅自修改这些部署设置。

### 步骤 1：创建管理员

| 字段或选项 | 默认值 | 是否必需 | 行为与校验 |
| --- | --- | --- | --- |
| 管理员用户名 | `admin` | 是 | 可修改，1–64 字节；及时显示格式错误，服务端最终校验 |
| 管理员密码 | 无预配置时为空；有预配置时只显示已配置状态 | 必须有有效密码；预配置时无需输入 | 手动输入默认隐藏，至少 8 个字符、最多 256 字节；预配置密码在服务端按相同规则校验，不回显 |
| 确认使用已配置管理员密码 | 仅有效预配置时显示，默认未勾选 | 预配置时必需 | 只确认使用服务端来源，不把密码填入页面 |
| 随机生成 | 不自动执行；预配置时不显示 | 否 | 浏览器安全随机生成 20 位密码，生成后显示以便保存，不自动提交；失败可手动填写 |
| 显示/隐藏密码 | 隐藏；预配置时不显示 | 否 | 只改变手动输入的显示状态，不改变密码 |
| 从导出的配置初始化 | 默认折叠、未选择文件 | 否 | 选择、预览、明确采用新格式业务配置；完整规则见“导入配置分支” |

手动路径沿用现有 Setup 的单个密码输入，不新增重复密码输入或强制注册信息；预配置路径不提供密码输入框。手动密码只保存在当前页面内存，预配置密码只由服务器读取，两者都不写入浏览器持久化存储、导出文件或日志。

“下一步”只检查输入或凭据使用确认，不创建管理员；存在字段错误、无效预配置或尚未确认使用时禁用。使用导入配置不会覆盖管理员凭据来源、使用确认或已输入的手动凭据。

### 步骤 2：首个域名与 DNS

此步骤按“域名 → DNS 目标与凭据 → 预览和确认 → 解析检查”顺序展示，并突出当前下一步操作；无需增加独立的域名或 DNS 步骤。

| 字段或选项 | 默认值 | 是否必需 | 行为与校验 |
| --- | --- | --- | --- |
| 首个通配符域名 | 空；导入时读取所选首个域名 | 是 | 可输入 `example.com` 或 `*.example.com`，统一为小写基础域名；禁止协议、端口、路径、多级通配符与无效标签，并保证控制台完整域名长度有效 |
| 控制台地址 | `https://caddyadmin.<基础域名>` | 自动生成，只读 | 随域名实时预览；普通 Setup 不提供自定义标签、端口或 Origin，登录后走控制台交接修改 |
| 域名访问属性 | 未配置（`null`） | Setup 不设置 | 普通 Setup 不展示或自动选择访问属性；登录后配置，发布启用业务服务前明确确认。控制台认证独立执行，来源限制默认关闭 |
| Caddy 访问 IP | 内置模式可采用浏览器地址栏中的有效 IP，支持公网或私网；无法建议或外部模式为空 | 普通内置模式必填；外部/测试模式可选 | 指访问设备能到达的 Caddy IP，不是初始化设备来源；外部模式填写外部 Caddy 的 IP，不是 Manager IP。仅填写一个 IPv4 或 IPv6，不含协议或端口 |
| DNS 记录预览与复制 | 自动根据域名、IP 生成 | 只读辅助 | 展示 `A` 或 `AAAA`、`*.<基础域名>`、目标 IP、仅 DNS（灰云）；可“复制 DNS 记录”，复制失败时保留可手动复制的文本 |
| Cloudflare API Token | 无预配置时为空且隐藏；有预配置时只显示已配置状态 | 普通内置模式必须可用；预配置时无需输入；其他模式不使用 | 不从业务导入文件读取，不提供明文回显；预配置时只由服务器读取，统一保存到受限运行 secret 文件 |
| 确认使用已配置 Cloudflare Token | 仅普通内置模式有有效预配置时显示，默认未勾选 | 该分支必需 | 确认使用当前服务端来源，不显示或重复提交 Token 内容 |
| 获取 Token 与权限 | 默认折叠 | 否 | 保留创建 Token、官方说明链接及目标 Zone 的 Zone Read / DNS Edit 帮助；不要求用户授权所有域名 |
| 浏览器 DoH | Cloudflare DoH | 有默认值 | 可切换 Google DoH；只提供现有固定服务，不增加任意 URL 输入；仅点击“检查 DNS”才发送查询 |
| 高级：服务器 DNS | 默认折叠；`1.1.1.1`，显式导入时采用文件值 | 必须有有效值，但通常无需填写 | 支持逗号分隔的 IP 或 IP:端口；可修改或点击采用服务器建议。它用于 Caddy DNS-01 和运行诊断，与浏览器 DoH 无关 |

普通内置模式的自动 DNS 操作接受可达的公网或私网 IPv4/IPv6，不再要求目标必须属于私网，以支持公网部署的首次使用。仍拒绝回环、未指定、链路本地、组播及 IPv4 映射形式等无效记录目标。这是 DNS 目标校验，不是客户端来源限制；此次不增加双地址目标编辑或其他 DNS 提供商。

服务端对 Token 的基本格式、目标 Zone 可见性、记录冲突和权限进行校验，错误响应不回传 Token 或模块原始日志。通配符覆盖一层子域，不包含基础域名本身；已有精确控制台记录可能覆盖通配符，必须核对。

#### 普通内置模式：DNS 操作顺序

1. **预览 DNS 变更**：域名、有效目标 IP、手动 Token 或已确认使用的有效预配置 Token 齐备后可点击。读取 Cloudflare 状态，展示新建/更新/复用、记录类型、名称、目标 IP、旧地址及旧代理状态；不修改 DNS。重复记录、CNAME 冲突或不匹配的控制台精确记录会阻止继续。
2. **确认 DNS 影响**：勾选“我已确认上述 DNS 记录及变更影响”。该勾选只确认当前预览，与最终初始化确认分开。
3. **确认 DNS 配置**：勾选后可点击，立即写入或复用 Cloudflare 记录，设置为仅 DNS（灰云）。先持久化操作意图及受限 Token，再执行写入；完成后反馈“DNS 配置已确认”。不等待传播，也不创建管理员。
4. **检查 DNS**：配置确认后执行浏览器 DoH 查询，检查控制台和随机一层子域的 A、AAAA。两种类型均需查询成功，总体至少有地址，所有返回地址均须匹配当前目标 IP；没有另一类型的地址可接受，但另一类型有不匹配地址时不能忽略。
5. **下一步**：DNS 配置已确认且当前浏览器检查通过后，执行服务器预检并进入步骤 3。有字段或配置阻断项则留在当前页；服务器解析器不响应等警告在步骤 3 展示，不把它与浏览器传播检查混为一谈。

DNS 结果表展示查询名称、所选 DoH、返回地址、是否通过及失败原因。失败时支持直接重查或切换 DoH；不要求重复写记录。成功提示仅说明所选解析服务返回正确 IP，不表示本机可达、服务器 DNS 可用或证书已经可信。

更换基础域名、目标 IP 或 Token，使原 DNS 预览、确认和检查失效，必须重新预览及确认。更换 DoH 只使浏览器检查失效，不重复 DNS 写入。更改服务器 DNS、管理员凭据或导入草稿使最终预检/确认失效，但不要求重复已经核对的同一 DNS 变更。返回上一步保留输入与仍有效的结果。

若写 DNS 时响应丢失，重试先核对持久化意图与实际记录，不能盲目重复覆盖。记录被他人修改时要求重新预览和确认。DNS 已写入但后续 Setup 未完成时明确显示这一事实，不承诺自动撤销外部记录。

| 选项或行为 | 外部 Caddy | `TEST_TLS=true` 的内置模式 |
| --- | --- | --- |

| Caddy IP | 可选，用于记录指引和 DNS 地址比较 | 可选，用于 DNS 地址比较 |

| 未填写目标 IP 的 DNS 结果 | 只显示解析结果，不标为“目标 IP 已核对” | 同左 |

外部模式的预检显示远端连通性和已有控制台 TLS/路由状态；本地校验不能证明远端模块、Token 或存储可用。远端实际不可达时不得显示“外部 Caddy 已就绪”，仍只能从有效的本地初始化结果进入交接说明。

### 步骤 3：核对并完成初始化

| 展示或选项 | 默认状态 | 规则 |
| --- | --- | --- |
| 管理员用户名 | 只读摘要 | 不显示密码、密码长度或 Token 内容 |
| 凭据来源与使用状态 | 只读摘要 | 分别显示“部署预配置，已确认使用”或“本次手动设置”，不显示内容；已预配置项没有补填输入框 |
| 首个域名、通配符与控制台地址 | 只读摘要 | 使用服务端规范化后的值；无 Public/Homelab 标签 |
| 部署和证书模式 | 只读摘要 | 区分内置 Cloudflare、外部 Caddy、隔离测试；证书状态不得提前显示为可信 |
| DNS 目标、记录变更结果、浏览器检查 | 普通内置模式展示；其他模式按实际结果展示 | 说明 DNS 确认已发生，完成初始化不会再次执行未经确认的变更 |
| 服务器 DNS | 只读摘要 | 可返回步骤 2 展开高级选项修改 |
| 初始化后的待办 | 只读说明 | 业务域名访问范围、上游许可在首次登录后配置；控制台 LAN/VPN 限制可选，默认关闭。普通路径没有服务，尚不许可任何上游。这里不增加访问属性选择、网段输入或网段确认 |
| 预检结果 | 自动展示 | 分为通过、警告、阻断；格式、冲突或实例状态问题阻断。普通路径空上游许可不属于错误 |
| 重新预检 | 可主动执行 | 保留输入，刷新结果并清除旧警告确认；预检不写 DNS 或创建管理员 |
| 我已理解上述警告，并确认继续初始化 | 有警告时才显示，默认未勾选 | 绑定当前配置和具体警告；后台复检出现新警告时要求重新确认 |
| 我已确认导入配置，服务仅保存为草稿 | 仅导入分支显示，默认未勾选 | 必须明确确认；不能当成发布服务的授权 |
| 上一步 | 可点击，提交中禁用 | 返回域名与 DNS，保留输入；按改动失效对应确认 |
| 完成初始化 | 无阻断项且必要确认已完成时可点击 | 按钮附近说明管理员与设置将保存、内置服务会重启、服务草稿不会自动上线、关闭页面不取消后台操作 |

点击完成时服务器再次核对尚未初始化、凭据格式及当前 Setup 会话的预配置使用确认、业务设置、导入草稿、预检警告、DNS 实际记录及确认指纹、现有快照归属；已有不属于本次初始化意图的启动快照会阻断，不删除数据来继续。浏览器 DoH 结果不替代服务器对 Cloudflare 实际记录和变更确认的核对；服务器普通 DNS 解析失败仍是明确警告，不重复作为强制传播门禁。

提交期间显示“正在提交…”，禁用重复提交和表单修改。内置模式生成仅包含控制台与必要引导入口的完整配置，保存启动快照，事务创建管理员和设置，再完成重启交接；显式导入的服务仍只入草稿。外部模式不加载远端配置。

字段或明确业务失败：留在对应步骤，保留输入并给出原因及下一步。503：保留输入，说明哪些操作可能已经完成。最终提交超时或响应丢失：转入结果核对，不能直接显示初始化失败或重新提交。只有核对确认未完成且没有在途操作时，才恢复表单让用户重试。

### 完成后：状态核对与入口交接

此阶段不要求再次填写配置，显示以下独立状态和动作：

| 状态或动作 | 展示与行为 |
| --- | --- |
| 初始化结果 | 明确区分“初始化已完成”与“正在核对初始化结果”；凭据与设置持久化成功不等于证书或路由已就绪 |
| Manager | 服务已响应、等待响应、暂不可用；不把不可读误判为未初始化 |
| 服务端 DNS | 已有解析结果或尚未确认；与浏览器 DoH 结果分开展示 |
| HTTPS 证书与路由 | 正在申请/核对、服务端探测通过、异常；测试 CA 始终标为测试；探测通过不代替用户本机访问 |
| 正式控制台地址 | 可见、可复制；复制失败可手动复制 |
| 重新核对状态 | HTTPS 交接页提供，恢复网络后继续核对，不重放初始化请求 |
| 打开正式控制台 | 用户主动点击，打开精确的生成地址；不因服务器探测通过而自动跳转 |
| 通过临时入口继续登录 | 仅内置模式且临时入口仍启用时提供，受认证和 Origin/CSRF 保护，不默认检查 LAN/VPN 来源；外部模式临时页只有只读交接状态 |
| HTTP → HTTPS 交接 | 初始化成功后恢复 HTTP 的 HTTPS 跳转，转到 IP HTTPS 交接页；说明临时证书提示，不能从 HTTP 反复提交初始化 |

关闭页面不取消后台初始化、重启或证书申请。重新打开时先核对初始化结果。正式入口尚不可达时，给出检查本机 DNS、路由、防火墙和签发状态的建议，不跳回 Setup 添加网段配置。

正式控制台必须经过受认证的浏览器访问确认，临时入口随后保留五分钟再关闭；服务器探测或单纯读取交接状态不能替代这次确认。首次成功登录后进入概览的引导任务，而非额外 Setup 页面。

### 导入配置分支：所有选项与影响

该分支仅显式展开时出现，不增加普通路径的步骤数量，不引入凭据导入。使用同样三个步骤，其中步骤 2 标题可显示“核对导入域名与 DNS”。

1. **选择 JSON 文件**：只读解析，检查当前新格式版本、60 KiB 大小、字段和业务结构。拒绝旧格式、未知敏感字段和无效配置，不采用部分有效内容。
2. **预览文件**：显示文件名、域名数量、服务草稿数量和导入范围；此时尚未改变向导表单。
3. **采用导入配置**：明确点击后采用域名列表、策略、服务器 DNS 与草稿。管理员密码和 Token 不从业务文件导入：有部署预配置时只确认使用，无预配置时手动填写；当前 Caddy IP 不从文件推断。
4. **选择首个控制台域名**：只有导入了多个域名时显示基础域名下拉列表，默认选文件中控制台所属域名；展示生成的 `caddyadmin.<所选基础域名>`。本次 Setup 只验证和启用这个首个域名的控制台入口，其他域名保留为未发布配置，登录后按需校验发布。
5. **核对导入摘要**：域名及访问属性、网络与上游策略、服务器 DNS、每个服务的名称/Host/启停状态只读展示；草稿列表可展开。不增加 LAN/VPN 编辑控件或独立网段确认；仅由最终“确认导入配置”整体授权采用文件内容。
6. **修改必要项**：仍可修改首个域名、当前 Caddy IP、服务器 DNS，以及无部署预配置时的手动 Token。改动后按当前候选配置重新验证所有引用和草稿；不能自动重命名服务。其他域名和网络策略留到登录后编辑。非标准控制台标签或 Origin 端口的导入文件明确拒绝，不静默转换。
7. **取消导入**：恢复普通初始化默认值，清除导入候选、草稿和导入确认，保留独立输入的管理员凭据；如已经确认写过 DNS，明确告知取消导入不会撤销外部记录，继续前必须重新核对当前域名的 DNS。
8. **完成确认**：步骤 3 列明将采用的配置和草稿数量，必须勾选导入确认。服务器重新校验，服务只保存草稿。策略缺失或不许可导入目标时阻断，用户可更换文件或取消导入，不要求在 Setup 增加上游许可表单。

导入的策略作为显式导入内容采用，不意味着 Setup 提供网络设置流程；存在导入上游许可时不再使用普通路径的“未许可任何目标”说明。文件中已有的控制台来源限制只保留为待发布草稿，不在初始化完成时自动启用；当前运行的 `console_lan_only` 仍为 `false`，管理员登录后再选择是否启用并发布。首个控制台所需设置生效，额外域名和业务服务均标为未发布，避免初始化顺带开放导入服务。

- [ ] 未配置访问属性的域名可登记、申请证书和保存服务草稿；发布该域名的启用业务服务时明确阻断并指向域名设置。
- [ ] 所有字段、默认值、按钮和高级入口与上述清单一致；普通路径不要求展开高级选项或导入配置。
- [ ] Compose 预配置密码、预配置 Token、只预配置其中一项及均未预配置四种情况分别按表展示；已配置项只有状态与使用确认，没有输入框、回显或覆盖按钮。
- [ ] Compose 明文配置和环境变量/`.env` 注入均可使用；未设置或空值显示输入，非空无效值明确阻断，重建容器后重新确认；不要求 secrets、额外文件或权限配置。
- [ ] 预配置状态 API 不返回凭据内容，旧进程的使用确认无效；运行 Token 由应用自动持久化，日志、页面和业务导出不包含密码或 Token。
- [ ] 初始化后重启不重新设置密码或用旧部署 Token 覆盖运行凭据；外部与测试模式不因本地 Token 缺失而阻断。
- [ ] 预览不写 DNS；确认 DNS 的影响与完成初始化的影响分别说明，两个动作均不可隐式代替。
- [ ] 域名、IP、Token、DoH 或服务器 DNS 改变时，按明确规则失效检查和确认，不重复无关外部写入。
- [ ] DNS 传播失败可以重查，记录冲突必须重新预览，服务器复检警告变化必须重新确认。
- [ ] HTTP 明文提示、仅内置模式临时登录、外部模式不保存 Token 或加载远端、测试 CA 标识均可见。
- [ ] 返回上一步、503、连接失败和最终结果未知均保留输入；最终提交结果未知时不盲目重试。
- [ ] 服务列表初始为空；显式导入服务只入草稿，额外域名待发布；第一次登录能继续配置网络与上游许可。
- [ ] 凭据不进入日志、摘要、导出文件或浏览器持久化存储；既有实例及未知归属快照不会被覆盖或删除。
- [ ] 初始化完成、服务端探测通过、本机正式入口可用三个状态分开；实际浏览器访问确认后才开始关闭临时入口。

## 首次登录与设置页

概览的首次任务引导管理员：配置业务域名访问范围 → 配置上游许可 → 添加首个服务 → 预览、校验和发布。业务选择“仅可信网络”时才引导配置该业务使用的可信网段；控制台来源限制是设置页的可选项，不作为引导中的必填任务或后续管理操作的门禁。其他域名按需添加，不成为必须完成的任务；管理员可以稍后继续，认证、业务校验和显式启用的访问限制始终由服务端执行。

设置页区分：

- 部署状态：版本、模块、内外模式、Token 配置状态，只读。
- 域名：列表、添加、编辑、删除、访问属性；控制台域名单独显示。
- 访问与上游策略：可选的“仅允许 LAN/VPN 访问控制台”（默认关闭）、可信网络、允许上游网段、许可服务名；额外禁止 IP 放在高级选项。启用控制台限制与配置业务可信网段是独立动作。
- 服务器 DNS：可编辑，说明用于证书 DNS 校验和运行诊断，与浏览器 DoH 选择不同；不声称它已经替代系统的上游解析器。
- 密码、Cloudflare Token 和配置导入导出：沿用已有安全规则。

表单保存只修改配置草稿，成功文案和未发布标记说明“尚未影响线上”；网络错误或 503 保留输入。首次上游许可也通过仅含控制台的配置预览与发布生效，随后可添加服务。

## 策略草稿、发布与生效

持久化区分候选业务设置、已生效业务设置及不可变修订。设置草稿与服务草稿共享一个单调修订号，防止组合读取错版本。保存设置做格式、域名引用和业务边界校验；完整 DNS/目标安全检查在预览与校验时按候选策略执行。

发布预览同时展示服务 Diff 和域名、访问范围、上游许可、解析器 Diff。校验绑定候选修订、完整候选策略、实际运行指纹及地址快照；设置改变后必须重新校验。收紧上游许可时指出受影响服务，禁止发布含不合法目标的配置，不静默停用服务。

成功发布持久化对应业务策略，与发布 JSON 一起供恢复核对使用。启动读取已生效策略，不能把未发布的设置草稿当成运行策略。

沿用“持久化候选与发布意图 → 加载 → 核对运行指纹 → 原子替换启动快照 → 事务记录成功”的顺序。在记录成功时更新已生效策略与发布记录；随后将一致的运行策略提供给 Manager 鉴权、Origin、配置生成和探测。消除启动时静态配置副本作为可编辑业务规则的来源；部署环境仍由进程启动配置控制。

策略更新期间采用旧、新访问规则的安全交集，或暂停受影响管理请求返回可重试的 503，不能出现 Caddy 已收紧而 Manager 按宽松规则放行的窗口。响应丢失、快照失败或进程退出进入 `uncertain`，按发布意图与实际运行核对策略，未核对前阻止新发布并保持管理边界从严。

仅当管理员启用或调整控制台来源限制时，拒绝发布把当前已认证管理来源排除在新范围之外，提示改用目标网络重新登录、核对后再提交；关闭限制或修改业务可信网段不隐式生成控制台限制。Origin 修改只能通过控制台交接处理。

在线回滚仍使用当前已生效域名与安全策略重新校验历史服务，并保留未发布的服务和策略草稿；历史服务引用已删除域名时明确阻止并解释原因。回滚不偷偷放宽安全策略。

## 控制台域名交接

管理员可把控制台移到另一已登记域名的一层子域。该操作单独预览和确认，不随普通域名改名自动发生。

先在持久化交接意图中登记新地址、旧地址、策略修订与运行指纹；旧入口继续服务，新入口使用相同认证要求，并只沿用管理员已明确启用的控制台来源限制，不因交接而新增网段门禁。新 DNS 和证书验证、浏览器实际登录新入口成功后，才明确确认切换并移除旧地址。

交接只精确许可这两个 HTTPS Origin，不使用通配 Origin、任意 Host 或转发头放宽。Cookie 仍为主机范围，用户需要在新地址登录；交接完成撤销旧会话。交接中的地址均保留，禁止业务服务占用。

交接未完成、网络断联或重启不能静默弃用旧入口；按持久化状态核对继续。普通收紧网络规则也不能跳过新来源验证。

## DNS、证书与外部模式

统一根据已登记域名生成通配符证书策略和逐域名证书概览，探测通过固定 Caddy 地址，失败显示未知。域名的互联网访问属性与证书是否公网可信分开表示。

新增域名先核对 DNS 与 Token 授权范围，再发布不含该域名业务服务的证书配置，让 Caddy 申请证书；真实 TLS 探测确认后才允许发布该域名业务服务。不能要求一个尚未加载的域名先具备证书，否则流程无法完成。首个控制台的可信证书门禁保留；隔离测试 CA 不计为公网可信。

普通设置保存不会写外部 DNS。登录后的域名配置复用已有 Cloudflare 预览与确认能力，并受鉴权、CSRF、指纹冲突保护；其他环境可说明由管理员维护记录。应用内 Token 持久化仍使用受限 secret 文件，不进入业务配置导出；部署时允许按上述规则用明文环境变量预配置。

外部模式不自动回退内置实例，不在 Setup 自动发布到远端。域名与策略发布继续保留实际远端 `admin`、`storage`；明确区分本地配置校验、远端加载与证书状态。

## 版本与数据边界

按照项目“仅支持当前版本、不保留旧兼容入口”的约束，新数据库使用新的 schema 版本，新业务导出使用新的格式版本；不添加运行时 Public/Homelab 兼容字段，不自动改写历史发布 JSON、不可变草稿或启动快照。

旧版本数据库和旧业务导出明确拒绝，保留原文件，不删除数据来绕过初始化；运维文档必须直说该变化影响已有实例，不能宣称原地无损升级。实现前需要在计划中固定新的版本号与错误文案。

## 验证与文档

- 领域测试：多域名、一层子域、重复及重叠、控制台保留、访问属性未配置时阻止发布启用业务服务、控制台来源限制默认关闭且独立于业务访问属性、空上游许可与全部解析地址安全。
- 仓储及应用测试：设置与服务修订冲突、不可变历史、校验失效、幂等、串行发布、回滚保留草稿、无效域名引用。
- API 测试：管理员鉴权、CSRF、精确 Origin、伪造来源头、设置读取与发布状态一致、503 保留语义。
- 入口访问测试：公网/内网 Setup、公网 DNS 目标、默认公网控制台登录、未认证管理请求被拒绝；登录后启用/关闭控制台来源限制，业务网段配置不联动启用控制台限制，内置/外部/临时入口一致执行。
- 预配置凭据测试：密码/Token 的四种组合、空或无效环境值、旧进程确认失效、API 不泄露、首次初始化后不再覆盖密码及运行 Token；隔离 Compose 验证明文值、环境注入和字面 `$` 的传递。

## 验收

普通用户仅填写管理员、首个通配符域名及必要 DNS 信息即可进入需要认证的控制台；管理员密码或 Cloudflare Token 已通过 Compose 预配置时，Setup 只确认使用，不显示对应输入框或要求再次填写。Setup 没有业务访问属性选择、网段配置、网段确认或初始化设备 IP 绑定，也不默认赋予首个域名“仅可信网络”。Setup 和初始化后的控制台均不默认限制公网来源，公网部署入口可达时可以完成初始化并登录；控制台 LAN/VPN 限制由登录后的管理员按需启用，首次引导不强制填写。管理员能添加并管理多个基础域名，每个域名独立选择访问属性，服务不再选择 Public/Homelab 分组。所有业务策略变化都可预览、校验、确认和追溯，草稿与运行状态清晰区分，断联与重启后仍可核对恢复。
