# 服务高级配置实施计划

> 使用 superpowers:executing-plans 与 test-driven-development。用户已授权按选定功能和服务级片段完整实现；在当前共享工作区保留已有修改，不提交或部署真实实例。

**Goal:** 实现四项常用选项与可检查的服务级片段，默认界面简洁，高级配置明确可控。

**Architecture:** 领域层处理高级字段和受限Caddyfile片段，生成完整JSON；应用层统一只读检查，HTTP新增受认证端点，前端和配置v2共用服务模型。

**Tech Stack:** 现有Go/Gin/SQLite与React/TypeScript/Vite，不加依赖。

**Spec:** [服务高级配置设计](../specs/2026-10-14-service-advanced-design.md)

## Global Constraints

- 上游固定IP、安全目标、TLS验证、访问策略和显式发布不受片段影响。
- 旧JSON无advanced保持原行为；历史和快照不改写，无schema变更。
- 片段4096字节，每方向32条头，头值2048字节，超时大于0且最多24小时。
- 明确拒绝敏感头、动态变量、未知指令及表单/片段冲突。

## Review Focus

- 相同advanced不同内存地址不产生Diff；修改高级字段必须产生Diff。
- 检查期间输入/修订变化不能把过期结果当成当前有效；检查不保存。
- 片段不能替换上游或控制台、插入文件/环境密钥或关闭TLS验证。
- 导入、回滚和发布重新应用同一规则，原始片段保留。
- gRPC与HTTP压缩分开，旧服务和默认端口不意外改变。

## Ledger

- 需求明确，采用当前会话实施。领域结构是唯一生成规则，片段为有支持列表的服务级Caddyfile语法，不实现完整实例编辑器。

- 2026-10-15 完成：四种上游协议、压缩、静态头规则、超时与受限片段；统一领域生成与只读检查 API；表单、详情、可展开 Diff、演示及配置 v2 往返。
- 独立审查发现并修复两个交互问题：关闭压缩删除字段以便转用片段；粘贴 gRPC 地址与协议下拉框共用压缩规范化。回归用例先失败、修复后通过，复查无新的重要问题。
- 最终验证：`make test`（Go race 与前端 30 文件、234 项）、`make check`、`make build`、`make integration`（6 项真实 Caddy 测试）、`make container-test`（内置、外部与自动初始化）和 `docker compose config --quiet` 均通过；最后的展示调整后再次通过完整前端测试和构建。Vite 仍提示现有单包超过 500 kB，无构建失败。
- 真实 Caddy 覆盖 HTTP 压缩、请求/响应头、504 超时、h2c/grpcs HTTP/2 与 trailer、TLS 名称拒绝，以及选项重载/原模型恢复；应用测试覆盖高级选项发布、在线回滚和较新草稿保留。
- 使用已有 Chromium 对桌面 1440px 与手机 390px 演示表单截图检查，无页面脚本异常或横向溢出；此项仅证明演示布局，不代替真实后端测试。
- 环境处理：默认 Go cache 只读，随后 `/tmp` 配额不足；构建缓存移到忽略的 `bin` 临时目录。长临时目录导致 Unix Socket 路径超限，改用 `/tmp/cav` 短链接后真实集成全部通过。这些是测试环境调整，未修改生产部署路径。
- 所有容器验证使用临时资源，未部署真实实例、使用真实 Token 或改动运行数据。公网 gRPC 客户端与实际远端模块/上游证书仍属于部署环境验收。
