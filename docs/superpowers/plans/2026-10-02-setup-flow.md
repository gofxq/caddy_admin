# Setup 流程优化实施计划

> 执行方式：当前会话直接实施，按测试驱动开发推进，最后统一审查和验证。

**目标：** 一次修复已审查的六类 Setup 问题，并将向导解析验证改为浏览器 DoH。

**设计：** 保留管理员、域名、网络、DNS、确认五步。浏览器通过明确选择的 Cloudflare/Google DoH 查询控制台与随机子域的 A/AAAA；服务器 DNS 保留在高级设置，供证书和运行诊断使用。后端继续核对 Cloudflare 实际记录、确认指纹、网络规则及快照归属，取消完成接口的普通 DNS 强制解析阻断。警告确认绑定当前设置和具体警告。

**约束：** 不增加依赖；不覆盖工作区原有改动；不操作真实部署、Token 或数据；不保存密码或 Token 到浏览器持久化存储。浏览器 DoH 通过不表示设备可达或证书已就绪。

## 任务

- [x] 浏览器 DoH：新增 `web/src/setup-dns.ts` 和对应测试，覆盖 A/AAAA、随机子域、全部地址一致、IPv6 规范化、NXDOMAIN、空回答、HTTP/网络/格式错误、超时、请求不含凭据。
- [x] 后端完成与警告：修改 `internal/application/setup.go` 和测试，取消普通 DNS 完成阻断；新增 `warning_fingerprint`，拒绝缺失或过期警告确认；保持记录冲突、未执行变更、快照保护和导入校验。
- [x] DNS 页面：修改 `Setup.tsx` 和测试，DoH 快捷选择独立于服务器解析器与记录确认；按状态突出操作并说明下一步；修改目标、Token 或域名使记录确认失效。
- [x] 连接与交接：首屏不可达显示连接失败和重试；提交响应丢失继续核对，未初始化时恢复表单；初始化成功与入口就绪分开展示，取消仅依据服务端探测自动跳转。
- [x] 字段和预检：域名/用户名及时反馈，解释网络用途；去除提交前重复预检，后端复检出现新警告时回到确认页重新确认；绑定警告指纹提交。
- [x] 文档与验证：同步 usage、operations、api、流程审查文档；运行前端测试、Go race 测试、静态检查和构建；运行适用的真实 Caddy 集成检查。真实浏览器/CORS、真实 DNS 和生产证书验收单独说明。

## 审查重点

- HTTP Setup 中随机 DNS 名称不依赖仅限安全上下文的 API。
- DoH 查询没有 Cookie、密码、Token、LAN 或上游策略；页面 CSP 仅允许已列出的服务。
- 切换 DoH、返回上一步、更改非 DNS 设置不会要求重复外部写入。
- 预检警告增加/变化不能沿用旧确认；完成接口 503 保留输入，网络断联不重放。
- DNS 查询超时、部分地址族失败或混合地址不得误报通过；交接页不将连接失败显示为已完成。
