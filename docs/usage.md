# 使用指南

Caddy Web Admin 面向专用 Caddy 实例，采用单实例、单管理员模式，不接管现网或导入旧 Caddyfile。界面包括「概览、服务、发布、证书、审计、设置」。安装、DNS 与访问边界见[部署与维护](operations.md)。

## 首次使用

Setup 只有「管理员 → 首个域名与 DNS → 确认」三个步骤，不填写 LAN/VPN 网段或上游许可，不绑定初始化设备。公网与内网入口均可打开；初始化后控制台来源限制默认关闭，管理操作仍须认证。

管理员密码至少 8 个 Unicode 字符、最多 256 字节。未预配置时可手动输入或安全随机生成；部署已配置 `ADMIN_PASSWORD` 或 `CLOUDFLARE_API_TOKEN` 时，对应项只显示状态并要求确认使用，不显示输入框或凭据内容。非空无效值须修正或清空部署值后重建容器。外部与测试模式不使用本地 Token。HTTP 会明文传输手动输入的凭据，建议使用 HTTPS。

首个域名可输入 `example.com` 或 `*.example.com`，控制台自动使用 `https://caddyadmin.example.com`。Caddy IP 支持公网或私网，指实际部署入口而非初始化设备来源。普通内置模式先预览 DNS 变更、明确确认写入，再由浏览器 DoH 检查；未传播可重查，无需重复写入。浏览器默认 Cloudflare DoH，可切换 Google；只发送控制台和随机子域的 A/AAAA 查询。服务器 DNS 高级选项默认 `1.1.1.1`，用于证书校验与诊断，与浏览器 DoH 独立。

预检警告须确认；后台复检变化时保留输入并重新确认。连接失败可重试，503 保留表单，提交结果未知时先核对，不盲目重放。初始化完成、服务端探测通过和用户本机能打开正式入口分别展示；正式入口由用户主动打开。详见[初始化说明](operations.md#初始化与访问边界)。

首次登录后，在设置中明确选择业务域名的「仅可信网络」或「允许互联网访问」，配置上游许可，再添加服务。首个域名初始为「待配置」；待配置域名可保存草稿，但不能发布启用的业务服务。初始上游许可为空，意味着拒绝所有上游。选择可信业务访问时配置可信网段；控制台的「仅允许 LAN/VPN 访问」独立且可选，默认关闭。设置保存只改变草稿，须经过预览、校验与明确确认发布才生效。

首次服务列表为空，初始化时显式导入配置除外。添加示例草稿需在维护终端执行：

```bash
docker compose stop caddy
docker compose run --rm --no-deps caddy manager seed-examples
docker compose start caddy
```

源码部署或外部模式使用各自的 Compose 文件组合；示例仅保存草稿，不自动发布。

## 服务与发布

在「服务」中新增、修改、启停或删除服务并保存草稿；这些操作不会立即影响线上。

在「发布」中查看业务 Diff 和只读 JSON，校验配置，核对影响后明确确认发布。校验有效期为 15 分钟；草稿、策略、DNS 或运行指纹变化后必须重新校验。

发布在后台执行，关闭页面不会取消。网络失败时先核对部署状态；`uncertain` 表示实际运行状态待核对，不能直接重试。审计记录用于追溯操作与草稿历史。

## 在线回滚

只有成功发布的版本可回滚。回滚按当前网络策略和 DNS 重新生成历史业务配置，保留尚未发布的草稿；失败或待核对的版本不能作为回滚目标。

## 配置导入导出

在「设置」导出域名、网络策略和服务草稿，或上传 v2 文件预览并明确确认替换草稿。现有实例沿用本机域名和网络策略，只替换服务草稿，不自动发布。新实例可在管理员步骤显式采用完整业务配置，核对域名、访问属性、策略和草稿；仍使用同样三个步骤，不增加网段输入。管理员凭据和 Token 由部署预配置确认或手动填写，不从文件导入。导入的控制台来源限制仅保留为待发布草稿，初始化不自动启用。旧 v1 文件明确拒绝。

导出不包含密码、Token、证书、发布历史或运行数据，不能代替完整备份。大小、字段限制、冲突处理与初始化导入边界见[配置迁移](operations.md#配置迁移)。
