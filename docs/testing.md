# 从零测试流程

命令在项目根目录执行。先完成「空白初始化 → 导出 → 现有实例导入」，再清空验证实例、通过导出文件初始化。当前仅支持新安装或完整的当前版本实例，内置模式支持 HTTP/HTTPS Setup；HTTP 会明文传输手动凭据，建议使用 HTTPS。

## 空白实例与草稿测试

需要项目源码和 Docker Compose；`make validation-up` 加载 `compose.build.yaml` 构建当前源码，不依赖已发布镜像。使用默认内置模式，不设置 `CADDY_ADMIN_URL`。以下清理命令只删除 `caddy-admin-validation` 验证项目及其测试卷，先保存需要保留的测试导出文件。

```bash
make validation-down
make validation-up
make validation-status
```

环境使用独立命名卷和随机回环端口，不读取真实 `.run/`。按输出的 443 TCP 宿主端口打开 `https://127.0.0.1:端口/setup`；远程主机通过受控 SSH 转发在本机浏览器访问。重建后重新查询端口。

1. 创建管理员，设置至少 8 个字符的新密码；填写首个测试域名，例如 `home.example.test`。
2. 核对 Setup 没有网段输入、设备来源绑定或默认访问范围选择；HTTP 手动凭据明文提示可见。
3. 填写可达、可信的 DNS 解析器。核对并确认未解析测试域名等警告；字段或安全阻断项必须修正。
4. 完成后通过 IP 临时入口登录，确认服务列表为空、控制台来源限制关闭。在设置明确配置域名访问范围和独立测试上游许可；禁止指向 Manager/Caddy 控制入口。测试 CA 下策略发布同样受证书门禁，添加含上游服务应使用显式导入的许可测试夹具，真实策略发布在专用可信证书实例或外部隔离模式验证。

验证覆盖默认 `TEST_TLS=true`，无需真实 Token，使用内部测试证书，浏览器信任警告属于预期。公网可信证书就绪前，内置模式禁止校验/发布。本轮只验证初始化、草稿、导入导出与数据保留。

默认隔离模式不代表公网可信，不能启用 Cloudflare，仍禁止校验/发布。真实域名测试另建专用实例，显式关闭 `TEST_TLS`，按向导提交专用测试 Token、预览并确认 DNS 变更；不要把真实 Token 用于自动测试。

## 现有实例导入导出

在「设置 → 配置导入与导出」下载文件，保存在测试卷之外。文件名附带 UTC 时间戳；文件只包含域名、网络策略和服务草稿，不含密码、Token、会话、证书或内部服务 ID。

| 操作 | 预期 |
| --- | --- |
| 修改或删除草稿，上传原文件 | 上传不保存；预览展示恢复草稿的变更 |
| 未确认覆盖 | 无法提交导入 |
| 明确确认导入 | 替换全部草稿，保留当前域名与网络策略，不改变线上版本 |
| 查看导入审计 | 可以打开对应历史草稿 |
| 预览后在另一个标签页修改草稿 | 导入返回修订冲突，要求重新预览 |
| 上传损坏 JSON、未知字段或不支持的版本 | 错误提示，不修改草稿；可重新选文件 |
| 将副本中的 `services` 改为 `[]` 并确认导入 | 清空草稿，保留线上与历史；可用原文件再次导入 |

文件最大 60 KiB，包含内网信息，请妥善保存；不能代替完整备份。

## 重启与新实例导入

```bash
docker compose -p caddy-admin-validation \
  -f compose.yaml -f compose.build.yaml -f compose.validation.yaml restart caddy
make validation-status
```

重新登录，核对草稿、启停状态和审计记录仍在，不重新出现初始化向导。

保存原始导出文件后，重复开头的清理与启动命令。在初始化管理员步骤上传并采用文件，设置新密码，核对域名、网络、DNS 与服务列表，明确确认草稿导入。完成后服务应保持未发布，旧密码、Token、证书与发布历史不会导入。当前向导支持 v2 多域名导入，不支持自定义控制台标签或 Origin 端口，会明确拒绝这类设置。

结束测试：

```bash
make validation-down
```

## 自动检查与真实环境验收

按[贡献指南](../CONTRIBUTING.md#本地开发)准备工具链和锁定的前端依赖，依次执行，避免资源争用造成超时：

```bash
make test
make check
make build
make integration
make container-test
```

各命令范围见[验证说明](verification.md)。容器验收需要 Docker、Python 和 curl，使用临时资源，覆盖内置 HTTP 初始化后切换 HTTPS、外部 HTTPS 初始化、导入导出、发布边界和重启；外部隔离模式覆盖实际发布。演示界面不能替代真实后端验证。

真实 LAN/DNS、Cloudflare 签发与业务访问在专用测试实例、专用测试域名上另行验证，关闭 `TEST_TLS`。从 HTTP 80 打开 Setup，检查 Token 申请链接、DNS 新建/复用/覆盖确认及冲突提示；确认后核对灰云记录和 HTTPS 交接。按[安装说明](../README.md#快速部署)和[运维说明](operations.md#初始化与访问边界)配置标准端口、DNS 和访问范围。可信证书就绪后，测试预览、校验、确认发布、业务访问、未登记域名隔离、在线回滚与重启。不要使用生产数据库、证书、Token 或生产 Caddy。
