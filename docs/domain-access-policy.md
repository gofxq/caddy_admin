# 域名与访问策略：当前方案与修改目标

核对日期：2026-10-14。本文保留变更前的域名与访问策略，并记录已实施的默认开放方案，供核对已有实例、导入配置及新实例的差异。

**状态：默认开放方案已实现。** 新实例首个域名及新增域名默认 `internet`，可信与上游网段覆盖全部 IPv4/IPv6，独立 `*` 许可全部合法服务名。已有实例和显式导入保持原策略；实际使用见[初始化流程](setup.md)与[使用指南](usage.md)。

## 目标与边界

让普通用户完成初始化后，能直接使用公网或私网 IP、Docker 服务名或 DNS 名称添加服务草稿，再预览、校验和确认发布，减少先去设置页理解网络许可的步骤。控制台来源限制和业务来源限制按需收紧，认证、上游安全检查及发布确认继续由服务端执行。

用户已明确要求默认值全部采用最开放模式，现已实现：业务与控制台来源不限制，上游 IP 与合法服务名默认全部许可，管理员可按需收紧。

继续面向专用 Caddy、单实例、单管理员。不增加多上游、路径路由、任意配置编辑或自动接管现网。

## 变更前方案（用于核对已有实例）

### 五个相互独立的概念

| 概念           | 配置与职责                                                           | 不能据此推断的事情                               |
| -------------- | -------------------------------------------------------------------- | ------------------------------------------------ |
| 域名归属       | `domains` 登记基础域名，服务用 `domain_id` 引用                      | 登记域名或取得通配符证书不等于已有业务路由       |
| 业务访问来源   | 域名的 `access` 与全局 `lan_cidrs`                                   | 不决定控制台是否限制来源，也不决定可代理哪些上游 |
| 控制台访问来源 | `console_lan_only` 与全局 `lan_cidrs`                                | 来源可访问仍须登录才能管理；可信网段不代替认证   |
| 上游目标许可   | `upstream_cidrs`、`allowed_names`、`denied_ips` 与系统受保护地址     | 许可代理目标不代表已对外发布服务                 |
| DNS 与入口     | 域名记录指向 Caddy IP；浏览器 DoH、服务器 DNS 和系统上游解析各有用途 | 能解析不等于网络可达、证书可信或业务已上线       |

### 域名与服务归属

- 域名保存为基础名称，例如 `example.com`；Setup 和设置保存接受前导 `*.`，去掉它后保存。域名名称统一为小写，并去除末尾点。
- 至少登记一个域名；ID 不能空或重复，名称不能重复或相互重叠，例如不能同时登记 `example.com` 和 `home.example.com`。
- 控制台必须是登记域名下的一层子域，普通初始化使用 `caddyadmin.example.com`，并绑定精确 HTTPS Origin。
- 服务必须是其 `domain_id` 指向的基础域名下的一层子域。`photos.example.com` 可以，基础域名本身、`a.photos.example.com` 或其他未登记域名不可以。
- 服务不能占用当前控制台或交接中的旧控制台域名。域名仍被草稿、已发布服务或控制台引用时，不能直接删除或改名。
- Caddy 仅为已启用服务生成精确 Host 路由；未知域名和未创建路由的子域不转发到默认业务上游，兜底返回 404。内置模式的 IP/localhost 临时管理入口是单独入口。

访问范围属于基础域名，影响它下面的所有启用服务；目前没有每服务独立访问范围。

### 业务访问来源

| `access`   | 当前含义       | 发布规则                                                            |
| ---------- | -------------- | ------------------------------------------------------------------- |
| `null`     | 待配置         | 可登记域名和保存符合上游策略的草稿；不能发布该域名下启用的服务      |
| `trusted`  | 仅可信网络     | 必须填写非空 `lan_cidrs`；Caddy 按 TCP 对端 IP 匹配，不匹配返回 403 |
| `internet` | 允许互联网访问 | 不添加业务来源网段限制；仍取决于监听、端口、路由和防火墙            |

`internet` 表示允许所有可达来源，不会创建公网 IP、修改防火墙或让私网地址自动变得公网可达。业务应用的登录由应用自身负责；控制台管理员登录不会保护业务应用。

### 控制台、Setup 与服务导览

普通 Setup 不按来源 IP 或 Host 是否私网限制访问，不绑定初始化设备。写操作有精确同源 Origin 校验、限速和初始化状态检查；首次有效完成初始化的提交创建唯一管理员。

初始化后 `console_lan_only=false`，所有能到达入口的来源可打开登录页。管理 API 保留服务端会话、Secure/HttpOnly/SameSite Cookie、精确 Origin、CSRF 和登录限速。

启用控制台 LAN/VPN 限制时，必须配置可信网段，当前设备也必须在新规则内；保存和发布均检查，防止直接把当前设备锁在外面。Caddy 与 Manager 执行来源策略，临时入口和交接中的旧控制台也受相应保护。仅填写 `lan_cidrs` 或把业务域名改为 `trusted` 不会自动启用控制台限制。

Caddy 将 TCP 对端写入 `X-Caddy-Client-IP`。Manager 只在 TCP 对端符合已确认的 Caddy 探测地址时采用该头；不信任任意 `X-Forwarded-For`。Caddy 前再放代理时，当前策略所见来源可能是该代理，不能据此假设能识别最终用户。

`/portal` 服务导览无需登录，沿用已发布控制台来源限制；只展示当前来源可见、已成功发布且启用的服务名称和访问域名。控制台开放且业务为 `internet` 时，这些名称和链接也向可达访客展示，不包含上游、备注或管理配置。发布执行中或待核对时返回重试提示，不展示可能过期的链接。

### 上游目标许可

当前上游采用明确许可，空 `upstream_cidrs` 意味着没有可用目标，**空列表不表示无限制**。

1. 输入 IP：必须落在 `upstream_cidrs` 内，并通过受保护目标检查。
2. 输入服务名：必须与 `allowed_names` 中的名称精确匹配，随后解析；全部返回 IP 均须通过相同网段许可和保护检查。两项是叠加条件，填写服务名不能代替网段许可。
3. 拒绝回环、未指定、链路本地、组播，以及明确保护的元数据地址；拒绝 `denied_ips` 和系统保留 IP。
4. 系统保留 IP 包括 Manager 本机接口及 Manager/Caddy 管理、探测端点的解析 IP；按 IP 保护，不因换业务端口就放行。无法确认系统地址时拒绝继续校验，不跳过保护。
5. 只支持 HTTP/HTTPS 和 1–65535 端口；HTTPS 上游必须校验证书。
6. 名称解析地址排序后，选一个 IP 生成固定 `Dial`；不会直接让 Caddy 任意重新解析并连接。发布重新校验目标，`Dial` 变化时要求重新校验。

因此，即使域名为 `internet`、上游名称已许可，草稿仍可能因网段未许可或解析到受保护地址而被拒绝。DNS 查询失败会保留输入并提示修正，不能绕过地址检查。

### 变更前初始化默认值与生效时机

| 项目                           | 普通 Setup 变更前值                     |
| ------------------------------ | ------------------------------------- |
| 首个业务域名                   | 登记，`access=null`                   |
| 控制台                         | `caddyadmin.<首个域名>`，来源限制关闭 |
| `lan_cidrs`                    | `[]`                                  |
| `upstream_cidrs`               | `[]`                                  |
| `allowed_names` / `denied_ips` | `[]` / `[]`；系统内置保护仍执行       |
| 服务器 DNS                     | `1.1.1.1`                             |
| 服务                           | 空；显式导入仅保存草稿                |

变更前环境预配置自动初始化复用相同默认设置，不会自动创建或发布业务服务。新实例显式导入采用文件中的域名和策略；控制台来源限制保留在草稿中，初始运行状态仍关闭，初始快照只含控制台所属域名且不含业务服务。现有实例导入只替换服务草稿。

设置和服务保存只更新草稿。变更前首用路径是「设置访问范围与上游许可 → 保存许可草稿 → 添加服务草稿 → 预览 Diff 与只读 JSON → 真实 Caddy 校验 → 明确确认发布」。无需先单独发布许可。

放开控制台、扩大仍用于限制访问的可信网段、将业务域名设为 `internet`，以及发布新增或重新启用的公开服务，都可能触发服务端放开访问确认。校验绑定修订、策略和运行指纹，有效期 15 分钟；待核对发布阻止新的发布。回滚按当前策略和 DNS 重新生成历史业务模型，保留未发布草稿。

### 部署可达性

默认 Compose 的 80/443 映射绑定宿主全部接口，实际可达性由宿主网络与防火墙决定。容器内 Manager 和就绪端口为回环，Caddy Admin 使用私有 Unix Socket。

外部模式通过明确配置的 HTTP(S) Admin API 管理专用 Caddy；HTTPS 验证信任链且不跟随重定向。外部 Manager 的宿主映射默认回环，Setup 映射默认全部接口。外部不可达不会回退内置实例，首次 Setup 不自动向外部 Caddy 发布。

## 已实施方案：初始化默认最开放

### 当前默认值

所有可选访问限制默认采用最开放值。普通 Setup 继续只有三步，不增加必填网段，也不推断初始化设备来源或自动改防火墙。这里的开放针对来源与目标许可；管理认证、受保护目标检查和业务发布确认仍执行。

| 项目 | 变更前值 | 当前默认值 |
| --- | --- | --- |
| 普通 Setup 首个域名 `access` | `null` | `internet`，允许所有可达来源 |
| 控制台 `console_lan_only` | `false` | 保持 `false`，不限制来源；管理操作仍须认证 |
| `lan_cidrs` | `[]` | `["0.0.0.0/0", "::/0"]`，可信范围默认覆盖全部 IPv4/IPv6 来源 |
| `upstream_cidrs` | `[]` | `["0.0.0.0/0", "::/0"]`，默认许可公网、私网及 VPN 网段中的安全 IP |
| `allowed_names` | `[]` | `["*"]`，许可所有合法上游服务名，无需逐个登记 |
| `denied_ips` | `[]` | 保持 `[]`，不增加用户自定义禁止目标；系统内置保护始终优先 |
| 服务器 DNS | `1.1.1.1` | 保持现有默认，可按环境修改；不属于访问限制 |
| 服务列表与业务发布 | 空、明确发布 | 保持现有行为，初始化不创建业务服务或自动发布 |

这些是新实例未导入配置时的默认值。私网、公网、CGNAT/VPN 和 IPv6 目标均可在通过安全检查后使用，不再要求先配置网段或服务名。网络可达性仍取决于路由、防火墙和实际监听。

`lan_cidrs` 为全网段时，选择 `trusted` 或启用控制台来源限制仍允许全部来源。管理员希望限制为 LAN/VPN 时，必须将全网段替换为实际可信网段；界面需要明确提示当前可信范围覆盖全部来源，不能把仅勾选开关描述成已经收紧访问。

`allowed_names=["*"]` 已由设置、上游校验及配置导入导出支持。仅把独立的 `*` 定义为全部合法服务名，不支持 `*.example.com` 等其他通配规则；非通配名称继续精确匹配。空列表继续表示不许可任何名称，不改变现有导入配置的含义。

所有服务名仍须合法、可解析，全部返回 IP 都须通过网段与受保护目标检查，再生成固定 IP 的 `Dial`。`*` 和全网段均不能放行 Manager、Caddy 管理入口、系统保留 IP、控制台域名或危险特殊地址（含 IPv4 有限广播）；HTTPS 上游证书验证和 DNS 变化重校验继续执行。

手动初始化和环境自动初始化共用同一默认构造函数，页面摘要、设置、导入导出校验与演示同步支持明确的开放值。当前字段可承载全网段与 `*`，无需为了默认开放增加额外模式开关。

### 交互与确认

当前首用路径为「完成初始化 → 登录 → 添加服务草稿 → 预览、校验、确认发布」。使用安全的公网或私网 IP、Docker 服务名或 DNS 名称均无需先去设置页。管理员收紧策略后的许可失败、解析失败或受保护目标拒绝仍须给出具体原因与处理指引。

- Setup 确认摘要明确说明：控制台登录页不限制来源，首个业务域名默认允许互联网访问，可信网段与上游网段覆盖全部 IPv4/IPv6，合法上游服务名默认全部许可；当前仅建立控制台，业务服务须另行发布。
- 手动 Setup 的最终确认呈现上述影响，不增加单独网络步骤。环境自动初始化沿用用户预配置启动的授权边界，状态页明确展示采用的默认策略；仍不自动发布业务路由。
- 概览不再要求新实例先完成访问范围配置或上游许可配置。设置页展示实际全网段和全部服务名许可，提供收紧入口；导入、显式清空或收紧后的提示仍按真实策略反馈。
- 发布新增公开服务继续要求明确确认，说明影响的域名；不能因 Setup 已采用 `internet` 而跳过发布的放开访问确认。
- 控制台开放时，服务导览会公开展示已发布公开服务的名称和域名，确认说明需涵盖这一行为。

为保持新建默认一致，登录后新增域名也默认 `internet`，保存与发布仍执行放开访问确认。已有域名、显式导入及用户主动选择的 `trusted` 或 `null` 不自动改为开放。

### 数据与现有实例

新的初始化默认值仅用于未初始化、未显式导入的新实例；登录后新增域名采用新的创建默认值。已有数据库设置、草稿、发布 JSON 和启动快照不能因升级、重启或环境变化被自动改成开放策略。

显式导入保留文件中的域名访问属性和上游许可，包括 `null` 和空列表；不能以新默认值覆盖用户配置。继续拒绝旧 schema v6 与旧 v1 导出，不引入兼容迁移入口。已有实例按设置草稿、校验及确认发布主动调整。

[AGENTS.md](../AGENTS.md) 与当前用户文档已同步新的默认值。[既有多域名设计](superpowers/specs/2026-10-03-managed-domains-design.md)保留待配置域名和空许可的历史记录，并注明由本方案替代；不作为新实例默认值说明。

## 实施与验收范围

1. 在 `ManagedSettingsForSetup` 统一生成上述最开放默认值，登录后新增域名默认 `internet`；保留导入优先和已有实例不变的行为。在统一业务层支持 `allowed_names` 中独立 `*` 的语义，同步配置导入导出与前端校验。
2. 同步 Setup 摘要、概览任务、服务页提示与演示默认值；确保提示与真实后端许可一致。
3. 同步初始化、使用、API、部署与验证文档及 AGENTS 中的当前默认规则，不改部署端口以代替业务策略。
4. 覆盖手动与自动初始化默认一致；空初始服务与仅控制台快照；显式导入不覆盖；已有实例不改草稿和运行状态。
5. 覆盖公网、私网、VPN 与 IPv6 安全 IP 默认可用，`*` 下合法服务名可用、非法名称拒绝；收紧后范围外 IP 或未许可名称拒绝；空列表继续拒绝。覆盖混合安全/危险解析拒绝、受保护目标在全网段内仍拒绝、HTTPS 上游验证和 DNS 变化重校验。
6. 覆盖未知 Host 404、业务 `trusted` 与控制台独立、全可信网段下开关不收紧且界面准确提示、替换为实际可信网段后限制生效、伪造转发头拒绝、新公开服务确认、收紧控制台防止锁定、服务导览可见范围及发布待核对状态。

验证命令按范围选择 `make test`、`make check`、`make build`；配置生成变化运行 `make integration`。容器验收在隔离环境确认 HTTPS 登录、保存服务草稿、确认公开发布、重启和在线回滚，并核对断联、待核对状态与草稿保留。不得使用真实 Token、生产数据库或生产 Caddy；自动测试不能代替目标网络的 DNS、证书及防火墙验收。

实施步骤与验证记录见[实施计划](superpowers/plans/2026-10-14-open-default-policy.md)。仅在隔离测试环境验收，不操作真实部署或用户运行数据。
