# Caddy Web Admin 界面设计规范

本文定义 Caddy Web Admin 的视觉与交互风格，适用于初始化、登录以及「概览、服务、发布、证书、审计、设置」。面向自托管、单实例、单管理员的专用 Caddy 控制台，让普通用户能清楚、安全地完成核心任务。

功能边界以当前代码和[使用指南](../docs/usage.md)为准；本文不代表新增功能计划。

## 1. 设计原则

- 任务优先：页面先说明当前状态，再提供一个明确的主要操作。
- 配置可核对：区分草稿、已发布版本、实际运行状态与待核对状态，不能仅用颜色表达。
- 少填信息：导入后复用文件中的业务配置，默认展示摘要，修改入口按需展开。
- 安静清晰：浅灰背景、白色面板、大标题、充足留白和克制的蓝色主操作。
- 扁平层级：列表、表格和摘要优先，避免装饰卡片和多层卡片嵌套。
- 用户可控：说明操作何时影响线上；发布、回滚、覆盖和删除需明确确认。
- 安全默认：不展示密码、Token、私钥或可能包含密钥的原始日志，不默认放宽网络策略。
- 同一套响应式界面：桌面和移动端共用 React 页面、业务模型和状态语义。

## 2. 视觉基调

- 页面背景使用浅灰 `#f5f5f7`，主体内容使用白色或接近白色的表面。
- 蓝色表示主操作、链接和当前导航；绿色表示检查通过，琥珀色表示警告，红色表示错误或危险操作。
- 状态背景保持浅色，文字和边框共同表达状态，不使用大面积彩色风险面板。
- 面板圆角以 `24px` 为基准，输入和按钮使用 `12px`；表格保持连续、易扫描的行结构。
- 使用系统字体栈，不依赖外部字体请求。页面标题字重 700，正文 400–500，关键数值 650–700。
- 桌面正文不小于 `13px`，移动端核心内容不小于 `14px`；仅辅助标识可使用较小字号。
- 分区间留白通常为 `24–32px`，相关字段之间为 `16–20px`。

主题 token 统一维护在 [src/styles.css](src/styles.css)，组件不另建颜色体系：

```css
:root {
  --page-bg: #f5f5f7;
  --surface: #ffffff;
  --surface-subtle: #fbfbfd;
  --surface-dark: #111827;
  --color-primary: #0066cc;
  --color-primary-hover: #0057b8;
  --color-primary-subtle: #edf5ff;
  --text-strong: #1d1d1f;
  --text-main: #2b2b2f;
  --text-muted: #6e6e73;
  --color-border: #e1e4e8;
  --color-positive: #1d7f38;
  --color-warning: #875000;
  --color-danger: #c40018;
  --radius-card: 24px;
  --radius-control: 12px;
}
```

## 3. 导航与布局

桌面沿用左侧导航和顶部上下文栏。导航顺序固定为「概览、服务、发布、证书、审计、设置」，当前页面使用蓝色文字和浅蓝底色。主内容标题直接表达页面任务，不使用营销文案。

- 主内容按「标题与主要操作 → 摘要与重要提示 → 列表或表单」组织。
- 概览指标最多四列；证书和信息面板按空间使用两列。
- 数据列表使用细边框和分隔线，主体面板不依赖厚重阴影。
- 毛玻璃仅用于导航与顶部栏；正文、表格、初始化摘要和错误提示保持实色表面。
- 不支持 `backdrop-filter` 时，导航回退为白色背景。

响应式沿用现有断点：

| 宽度 | 布局 |
| --- | --- |
| 大于 `1150px` | 左侧固定导航、完整上下文栏、多列摘要 |
| `801–1150px` | 紧凑侧栏，保持中文导航和图标 |
| 不大于 `800px` | 顶部横向导航，表单与详情单列，摘要按可用宽度排列 |
| 不大于 `650px` | 初始化面板铺满屏幕，步骤与单列操作清晰可读 |
| 不大于 `400px` | 配置摘要的标签与值上下排列，长域名和 CIDR 自动换行 |

移动端按钮、输入、导航和展开入口的触控高度至少 `44px`。表格允许横向滚动，不能压缩域名、上游、指纹或错误内容到不可识别。

## 4. 初始化与导入

### 手动初始化

手动初始化采用「管理员 → 域名 → 网络 → DNS → 确认」流程；导入配置采用「管理员 → 核对配置 → DNS → 确认」。DNS 步骤桌面将目标地址、Token 和解析器并排展示，小屏单列；保留清晰的步骤导航，不裁切错误与查询结果。默认管理员名为 `admin`。根据服务器看到的私有来源地址，建议 IPv4 `/24` 或 IPv6 `/64` 网段并预填可信网络与上游网络；回环、链路本地、公网或无效地址不预填。建议不代表实际网络拓扑，Docker/NAT 下必须核对，用户可以修改。DNS 解析器默认 Cloudflare `1.1.1.1`，提供 DNSPod、阿里 DNS、Cloudflare、Google 快捷选择，也支持自定义 IP/端口；当前不支持 HTTPS DoH。导入配置优先，不被默认值覆盖。

### 从配置初始化

在管理员步骤上传业务配置 JSON，核对文件摘要并点击「采用导入配置」。下一步集中核对自动读取的域名、网络策略、DNS 解析器及服务草稿；展开「修改导入设置」即可调整，不重复填写。

密码与 Cloudflare Token 仍须重新填写。普通内置模式显示 Token、预览、确认配置与检查 DNS 入口，申请链接和最小权限说明按需展开。「预览 DNS 变更」只读预览；勾选变更影响后「确认配置」立即写入 Cloudflare；「检查 DNS」独立只读查询，不再次写入。结果表展示每个解析器查询的控制台和随机一层子域、返回地址与结果；未通过时保留输入供重查。配置确认与目标 IP 查询均通过后才能进入最终确认，提交前服务端仍强制复查。

外部模式和 `TEST_TLS=true` 明确说明不使用本地 Token；仍可检查 DNS，未填目标 IP 时结果只代表解析成功。返回上一步、失败和冲突保留输入，相关修改使旧检查与确认失效，须重新检查。

- 配置文件不含管理员密码、Token、证书、发布历史或运行数据，不能用作完整备份。
- 当前初始化只支持标准 Homelab 配置：无 Public 域名，控制台为 `caddyadmin.<Homelab域名>`，Origin 为对应的标准 HTTPS 地址。其他配置明确拒绝，不静默改写。
- Caddy IP 不从文件中推断；内置模式可建议当前访问的内网 IP，外部模式须填写外部 Caddy 地址。
- 外部 Caddy 的 DNS 与证书凭据在远端配置，初始化不自动发布到外部实例。
- HTTP 页面明确说明密码与 Token 会明文传输，仅用于可信内网；完成后切换 HTTPS。
- 预检和 DNS 预览期间禁用相关输入与重复操作，显示进行中状态。
- 提交响应丢失时核对交接状态，不能自动重放初始化请求。
- 导入服务以草稿保存，初始化完成后仍须走配置校验与明确确认发布的流程。

## 5. 核心业务页面

| 页面 | 优先展示 | 主要交互要求 |
| --- | --- | --- |
| 概览 | 草稿、发布与实际运行摘要，以及下一步行动 | 首次服务为空时引导新增服务，不自动添加示例 |
| 服务 | 名称、分组、域名、上游、草稿启停状态 | 新增、编辑、启停和删除只修改草稿，反馈说明需发布才影响线上 |
| 发布 | 业务 Diff、只读 JSON、校验结果和发布历史 | 保存草稿 → 预览 → 校验 → 明确确认发布；待核对状态阻止新发布 |
| 证书 | 域名、证书有效期、探测结果与可信状态 | 探测失败显示未知，测试 CA 不显示公网可信，不提供私钥入口 |
| 审计 | 时间、操作、对象与结果 | 支持追溯核心操作，不输出敏感值 |
| 设置 | 业务设置、Token 配置状态、密码维护和配置迁移 | Token 输入不回显已有值；导入现有实例时只替换草稿 |

在线回滚仅针对成功版本，说明将按当前策略和 DNS 重新校验历史业务模型，并保留未发布草稿。发布在后台执行，关闭页面不代表取消；页面明确区分成功、失败和结果待核对。

当前不增加多用户、多实例、主动健康检查、多上游、路径路由、流量图表、任意配置编辑器或项目级备份恢复入口。

## 6. 组件规范

### 摘要与列表

- 摘要使用标签和值配对的定义列表；长域名、地址和策略自动换行。
- 状态与数量优先，避免与核心任务无关的指标卡。
- 服务列表每行保留可识别的服务名、域名和上游；操作按钮有明确文字或可访问名称。
- 已启用草稿不等于已上线，状态文案必须标明其口径。

### 表单

- 复用现有 React、Base UI 组件和统一表单样式，不另引入桌面或移动端组件库。
- 标签常驻，不以 placeholder 代替标签；辅助说明贴近字段。
- 普通字段先显示，高级网络规则等按需展开。字段辅助说明收进问号提示，支持悬停、键盘聚焦与点击，Escape 关闭；触屏也可读取。安全警告、操作影响、错误与确认条件始终可见。
- 删除营销口号、装饰性英文副标题与重复导航文案，保留功能标题、状态和下一步操作。
- 表单校验与权限规则由服务端承担；前端负责阻止明显缺项并呈现反馈。
- 网络失败、503 或冲突时保留输入，解释下一步如何检查或重试。
- 设置新密码时提供「随机生成」和显示/隐藏按钮；仅在用户主动生成或显示时展示输入中的密码，不读取已有密码。使用浏览器安全随机源，生成失败保留输入并提示手动设置；修改密码表单自动同步生成值到确认栏，生成不会提交或自动复制密码。

### 按钮与确认弹窗

- 页面只突出当前最关键操作，其他操作使用描边或文字按钮。
- 发布、回滚、删除、覆盖草稿及修改 DNS 先说明影响，再要求明确确认。
- 复用现有 Base UI 弹窗；复杂确认可以加宽，移动端保持单列并允许内容滚动。
- 进行中按钮显示动作名，例如「正在预检…」「正在提交…」，禁用重复提交。

## 7. 状态与反馈

- 加载：使用现有加载组件或行内状态，只占当前任务区域。
- 空状态：说明为什么为空，并提供一个可完成核心任务的入口。
- 错误：说明失败原因、影响和下一步，允许重试；不把网络错误当成业务失败。
- 成功：说明已保存草稿、已发布或已完成初始化，不能只写「成功」。
- 警告：保留文字说明；需要继续确认时使用明确复选框，不能自动勾选。
- 待核对：明确提示正在读取实际状态，避免用户误以为可以直接重新发布。

## 8. 可访问性与动效

- 状态同时使用文字与颜色，键盘焦点清晰可见。
- 步骤指示保留文字并使用 `aria-current="step"`；字段标签常驻，查询结果不能仅凭颜色区分。
- 错误使用 `role="alert"`，异步结果使用适当的 `role="status"`。
- 蓝色主操作和浅色面板保持足够对比；登录页使用居中表单，保留品牌、账号密码和密码重置说明。
- 动效只用于按钮、浮层与状态过渡，通常 `120–240ms`，不添加背景循环动画。
- 遵循 `prefers-reduced-motion`，关闭非必要动画与过渡。

## 9. 落地与验证

- 公共视觉 token、布局和响应式规则维护在 [src/styles.css](src/styles.css)，共享摘要组件复用同一份业务信息。
- 保持当前 React + TypeScript + Vite 技术栈和已有 API，不因视觉改动新增依赖或外部请求。
- 页面行为变更补充 Vitest 交互测试，覆盖主路径、修改、错误重试和明确确认。
- 前端目录执行 `corepack pnpm test` 与 `corepack pnpm build`；安装使用 `corepack pnpm install --frozen-lockfile`。
- 使用 `make web` 在 `127.0.0.1:5177` 检查演示界面；这是演示 API，不代表真实部署验收。
- 在桌面和移动尺寸检查导航、长内容换行、焦点、触控目标和确认流程。
- 涉及初始化、发布或部署协议时，按[验收边界](../docs/verification.md)追加后端、真实 Caddy 或隔离容器验证。
- 用户可见行为变化同步[使用指南](../docs/usage.md)和[部署维护说明](../docs/operations.md)，不把尚未实现的功能写成已提供。
